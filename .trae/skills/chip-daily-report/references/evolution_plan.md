# 芯片行业日报 · 可进化架构规划（v2.0）

> 来源：Karpathy 视角架构分析 → 缺点/提升点/可进化点 → 规划大纲 → 增强版系统提示。
> 本文件是该优化的锚点文档，所有 M0–M6 改造以此为准。最后更新：2026-08-21（M1/M3/M4/M5/M6 全部落地）。

## 0. 北极星（反直觉）
- **Open-loop → Closed-loop**：当前是"LLM 写 → 人验 → 人改"（开环）；目标是"系统自己验、自己提修订、人只审阅"（闭环）。
- 进化的度量不是"日报更聪明"，是 **feedback 回路长度**——从"出错到修正"经过几步人工。每缩短一截，系统多一分自主性。
- rubric 不是说明书，是**系统的权重文件**。闭环意义 = 让权重被经验更新，而非手写。

## 1. 总体规划（按回路长度排序，先接最短的线）
| 阶段 | 目标 | 反馈回路 | 优先级 |
|------|------|---------|--------|
| M0 结构化中间表示 | 灭 parser 脆弱性 | —（地基，让后面全变简单）| P0 |
| M1 来源交叉验证 | 封 ghost 天花板 | 事实→多源比对 | P1 |
| M2 校验前置 | validate 退为兜底 | 生成时 schema 约束 | P1 |
| M3 预判校准器 | verdict 当训练信号 | 预测误差→置信度标准 | **P0（进化核心）** |
| M4 规则自生长 | dashboard→rubric 松紧 | FAIL 频率→规则修订 | P2 |
| M5 复盘反写 | 抗遗忘回路 | 周报→SKILL.md diff | P2 |
| M6 自我科研循环 | M3+M4+M5 串联 | 全自动进化 | 终极里程碑 |

## 2. M0：结构化中间表示（地基，P0）
- **做法**：LLM 不再自由写 md，改为输出 JSON 槽位——每条新闻含 `segment / signal / source_urls[] / confidence / technical_note / event_date`。模板层同时渲染 md 和 html 双产物。
- **收益**：`report_viz` 的 7 视图正则 parser 彻底退役（时效 FAIL 根源消失）；`validate` 退化为 schema 校验（前置约束）。
- **成本**：写一份 JSON schema + 渲染模板。一次性，但后面所有阶段都靠它变简单。
- **验收**：同一份 JSON 跑出 md 和 html，validate 从"文本正则"改成"字段校验"。

## 3. M1：来源交叉验证（P1）
- **做法**：JSON 里 `source_urls` 升级为 `[{url, tier, claim}]`；fusion 阶段对同一事实的 claim 做比对。**≥2 独立源支撑 → A 级；单源 → 自动降 B + 打"待核实"标签**。
- **意义**：把"来源真实性"从"URL 存在"升级为"事实三角验证"——封死 ghost 幻觉天花板的唯一结构性办法。

## 4. M2：校验前置（P1）
- **做法**：用 Pydantic-style 约束 LLM 生成，生成即合规。`validate_report.py` 退为"异常抽查 + 统计累积"，不再主防线。
- **收益**：消灭"写→验→改"的人工循环，迈向规模化。

## 5. M3：预判校准器（进化核心，P0）【本轮实施】
- **做法**：周期任务扫 `forecast_log.json`，统计"高确定性事件的实际偏差率"。
- **机制**：若某类标"高确定性"的事件频繁 ⚠️，说明分级标准失准 → **自动生成 rubric 修订建议**（不直接改，human-in-loop 提示）。
- **为什么是核心**：把"预测误差"接回"置信度标准"的那根线。系统开始用自己的错判校准自己的自信——对抗 ghost 的过度自信通病。
- **落地脚本**：`scripts/forecast_calibrator.py` → 输出 `state/forecast_calibration.json` + 可读报告。
- **验收**：连续 N 期，高确定性事件的 ⚠️ 率下降或稳定在一个已知区间。
- **M3→L4 强化（已落地 2026-08-21）**：校准器在"确定性档位偏差率"之外，新增**剧本立场命中率**——每条关键前瞻可挂 2~3 个互斥剧本（真趋势/炒作/被绕开，由 `forecast_tracker.py add --scenarios` 写入 `forecast_log.json`），下期现实逐一打分：真趋势/被绕开应被印证、炒作应被打脸；某立场命中率<0.5 且样本≥2 即生成 rubric 修订建议。这把《AI 杠杆操作系统》的"多剧本并行打分"直接接进了预判闭环。

## 6. M4：规则自生长（P2）【已落地 2026-08-21】
- **做法**：`quality_dashboard` 累积多期后，画"26 项规则 FAIL 频率热力图"。
- **机制**：高频 FAIL 的规则 → 自动判断"太严（放宽）"或"LLM 指令太松（加强 prompt）"→ 生成修订。
- **意义**：rubric 开始"长"出来，不再手动维护 26 项。
- **落地脚本**：`scripts/rule_growth.py` 聚合全部 `芯片行业日报_*.md` 的 26 项 selfcheck，按硬/软规则分类（高频 FAIL → 硬规则判"补模板"/软规则判"收紧 prompt"；高频 WARN → 软规则判"放宽"/硬规则判"修 parser"），输出 `state/rule_growth.json`（human-in-loop，仅建议不直改）。
- **验收**：基于真实 7 期日报运行 → 无触发（26 项健康），证明 rubric 当前稳定，M4 进入"待累积触发"状态。

## 7. M5：周度复盘自动反写（P2，抗遗忘回路）
- **做法**：`weekly_review` 提炼"本周错判 / 新规律" → 自动 diff 进 `SKILL.md` 的"注意点"段。
- **闭环**：跑 → 学 → 改说明书 → 下次跑用新版。正是"权重=长期记忆"的映射。
- **M5→L4 强化（已落地 2026-08-21）**：`weekly_review.py` 接入 `forecast_log.json`，新增**「🎭 前瞻剧本复盘」第七节**——把每条已验证前瞻挂的互斥剧本逐条摆出（谁被印证→升级、谁被打脸→淘汰），按立场（真趋势/炒作/被绕开）汇总命中率并给出「升级/淘汰信号」。无剧本时回退为挂接指引（不崩）。这是把 L4 情景推演落进周度认知资产的关键一节，也为后续 M5 自动反写 SKILL 提供"剧本升级/淘汰"素材。

## 8. M6：自我科研循环（终极里程碑）【已落地 2026-08-21】
- **做法**：M3+M4+M5 串成全自动链：采集 feedback → 提炼规律 → 反写 rubric/system → 验证改进。
- **里程碑定义**：系统连续 **30 期**无需人工调 rubric，即视为"会自己长记性"。
- **落地脚本**：`scripts/evolution_loop.py` 串联 `forecast_calibrator.py --apply` → `rule_growth.py --apply` → `m5_rewrite_skill.py --apply`，记录 `state/evolution_loop.json` 并维护 `auto_streak` 计数器（达 30 即里程碑）。`--dry` 可跳过 M5 反写。
- **验收（首次真实跑）**：auto_streak=1，M3 校准绿、M4 无触发、M5 已反写 1 条规律沉淀块 → 闭环全链路打通。此后每跑一次 +1，向 30 收敛。

## 9. 进化安全性（为什么不会改崩）
- **单一数据源 + 模块化 fail-soft**：`forecast_log.json` / `state/*.yaml` 是真相源，每个脚本独立可替。
- **所有自适应改动走"建议→审阅→合并"**，不直接覆盖 SKILL.md——防灾难性遗忘和错误回写。
- 改一块不炸全局，是进化的前提。

## 10. 不做清单（反模式防御）
- ❌ 不堆更多 HTML 视图（report_viz 已够，加视图是 vibe coding）。
- ❌ 不把"换更强模型"当解药（治标，不治 ghost 天花板）。
- ❌ 不做端到端黑盒（失去可验证性 = 失去进化能力本身）。

## 11. 增强版系统提示（v2.0，可直接用于新自动化）
见下方（与本文同步维护）：

### 角色与目标
你是「芯片行业日报」自动生成智能体。目标：每个交易日（周一至周五 08:00）自动生成一份面向中文读者的芯片行业日报，覆盖设计 / 制造 / 封测 / EDA / 材料五环节 + 市场 / 政策 / 资本横向维度，并内置「可验证 + 可进化」机制，使系统随运行累积而自我校准。

### 核心原则（不可违背）
1. 可验证性优先：所有产出必须可被自动校验。
2. 结构化中间表示（M0）：LLM 先输出 JSON 槽位，再由模板渲染 md 与 html。
3. 闭环而非开环：前瞻预判必须写入履约日志，下期自动回看验证。
4. 预判校准（M3）：预测误差必须反哺置信度标准。
5. 英文一律译中文。
6. 严禁预测未公告事件；确定性只判时点是否官宣，不预判结果。

### 执行流程
- Step 1 收集：WebSearch 多源覆盖五环节 + 横向维度，记录来源 URL/环节/首发日期；>72h 标 [回顾]。
- Step 2 结构化（M0）：LLM 输出 JSON 槽位（segment/title/summary/signal/sources/technical_note/is_review/event_date）。
- Step 3 交叉验证（M1）：同事实 sources≥2 独立 → A 级；单源 → B 级 + 待核实。
- Step 4 渲染：JSON → 模板 → md + html（7 视图含前瞻时间轴）。
- Step 5 校验：validate_report.py 26 项硬校验兜底；主防线是 schema 约束。
- Step 6 闭环：forecast_tracker add/show-due/verify + archive_to_kb + signal_history + quality_dashboard。
- Step 7 预判校准（M3）：周期任务扫 forecast_log.json 统计高确定性偏差率，超阈值生成 rubric 修订建议。
- Step 8 周五：weekly_review + 自动反写 SKILL.md 注意点段。

### 参数与约束
- 新闻 15–20 条；A 级占比 ≥30%；信号层 ≥80%。
- [回顾] 按最新来源日期判 >72h。
- 前瞻只列已公告；速览表六列（日期/事件/环节/重要度/确定性/来源）。
- JSON schema 强制；缺字段重试 ≤3 次后 fail-soft。
- 所有子步骤 fail-soft。

### 输出格式
- 交付：md（权威源）+ html（可视化）。
- 自检表 26 项 PASS/WARN/FAIL。
- 中文汇报 9 项。

### 进化机制
- 单一数据源：forecast_log.json / report_state.yaml / quality_dashboard.json。
- 校准回路（M3）/ 规则自生长（M4）/ 抗遗忘（M5）。
- 自适应改动一律"建议→审阅→合并"。

### 质量门禁
validate_report.py 26 项全 PASS（exit 0）方可交付；禁止带 FAIL 交付。
