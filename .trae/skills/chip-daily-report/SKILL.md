# Chip Daily Report

> 类型 P4：产物生成型 · v4.0 高效架构（流程合并+前置判定）

## 设计哲学

- **信源优先**：每条新闻必须可追溯至原始来源，拒绝二次转载未标注出处的内容。
- **产业链完整性**：宁可某环节标注"暂无动态"，也不省略环节——完整性是日报可信度的基石。
- **时效性优先**：默认覆盖最近一个工作日，超72小时的内容需标注"回顾"。
- **中立客观**：只汇总事实，不做评论、不做预测、不做投资建议、不做技术分析。
- **来源分级**：权威源优先，聚合页次之，社媒禁止——来源质量基于URL域名判定，不依赖display text。
- **执行闭环**：规则必须可执行、可验证——Rubric是门禁不是装饰，校验脚本是硬约束不是建议。

生成带来源和时间戳的芯片行业日报，覆盖设计、制造、封测、EDA、材料、设备等全产业链。

## 文件结构（本 skill 是模块化系统，不是单一文档）

| 文件 | 职责 | 何时加载 |
|------|------|----------|
| `SKILL.md`（本文件） | 主控：流程编排、输出格式、门禁规则、失败处理 | 始终加载 |
| `references/sources.md` | 分级动态源库（A/B/C级权威源清单+URL域名+搜索关键词模板） | Step 2 搜索时加载 |
| `references/classification.md` | 产业链分类判定规则（含正反例+存疑仲裁） | Step 3 分类时加载 |
| `references/rubric.md` | 13项门禁检查清单（详细判定标准+PASS/FAIL示例+Rubric-Step映射） | Step 5 自检时加载 |
| `scripts/validate_report.py` | 可执行校验脚本（硬约束，非建议） | Step 5 自检后运行 |

**关键**：本文件只含流程概览。每个Step的详细规则在对应引用文件中，按需加载以降低注意力负担。

## 生成流程（6步高效流程，v4.0合并优化）

> v3.2→v4.0 变更：10步→6步，合并时效标注/去重/排序到搜索阶段，来源分级即时判定，目标单次通过门禁。

### Step 1: 确认范围（5秒）
- 询问/确认日期范围（默认最近一个工作日）和关注领域
- **非交互模式**（如定时任务）：使用默认值（最近一个工作日），不等待用户输入
- 输出：`[日期范围]` + `[关注领域]` + `[生成时间]`（用于后续72小时计算基准）

### Step 2: 搜索+分级+筛选（一站式，~3分钟）
- **【强制】先执行文件读取**：读取 `references/sources.md` 获取A级域名清单和搜索关键词模板
- **搜索策略**：按5环节搜索，**优先使用 `site:A级域名` 限定搜索**（如 `site:cls.cn 半导体`、`site:semi.org equipment`），确保A级来源占比≥30%
- 对每条搜索结果**即时判定来源级别**（只看URL域名，不看display text），C级直接丢弃
- **即时去重**：搜索时发现同一事件多来源→立即合并为一条，标注多个链接
- **即时时效标注**：搜索时根据发布日期与生成时间的差值，>3天立即标注`[回顾]`
- 若A级 < 30%→**立即补充搜索**（不加额外步骤，在当前搜索阶段补搜即可）
- 输出：已分级、已去重、已标注时效的候选新闻列表（每条含：标题/URL/URL域名级别/日期/时效标签/摘要）

### Step 3: 分类+摘要（一站式，~2分钟）
- **【强制】先执行文件读取**：读取 `references/classification.md` 获取分类规则和存疑仲裁表
- 对每条候选新闻：确定归属环节 + 压缩摘要（3-4句，50-100字，保留主体+事件+数据+影响）
- 软件平台/SaaS/市场分析等不纳入
- 每个环节内按重要性排序：影响范围 > 技术突破 > 市场规模 > 企业动态
- 输出：分类完成、摘要压缩、排序确定的新闻列表

### Step 4: 组装日报（一次性做对，~1分钟）
- 按输出格式模板组装，**组装时一次性检查以下易错项**（防抖：减少门禁往返）
  - ✅ 头部元信息：生成时间、覆盖范围、新闻总数（必须与实际条数一致）
  - ✅ 今日要点：1-3条最重要新闻
  - ✅ 5个环节标题全部出现（无新闻标注"今日暂无重要动态"）
  - ✅ 每条新闻的[回顾]标签已标注（超72小时）
  - ✅ 每条摘要3-4句（不过长）
  - ✅ 来源分级统计与实际URL域名一致
  - ✅ 无附录越界
  - ✅ 尾部免责声明 + "---"分隔线
- 输出：日报草稿（含自检结果小节）

### Step 5: Rubric自检+脚本校验（~30秒）
- **【强制】先执行文件读取**：读取 `references/rubric.md` 获取13项检查标准
- 逐项检查13项Rubric，显式输出自检结果表格
- **【强制】运行 `scripts/validate_report.py` 进行硬校验**
- 若有FAIL项 → 按映射表修正 → 重新组装 → 再次校验（目标：单次通过）
- 输出：最终日报

### Step 6: 保存+同步（~5秒）
- 保存日报到工作目录，命名：`芯片行业日报_YYYYMMDD.md`
- 输出：完成确认

## 自检结果

| # | 检查项 | 结果 | 说明 |
|---|--------|------|------|
| 1 | 产业链完整性 | PASS | [具体说明] |
| ... | ... | ... | ... |
| 13 | 来源质量 | PASS | A级X条/共Y条=Z% |

**来源分级统计**（基于URL域名判定）：
- A级（权威）：[列出A级来源域名] = X条

**格式说明**：
- 报告头部必须包含生成时间、覆盖范围、新闻总数三项元信息
- "今日要点"精选1-3条最重要新闻，用一句话概括
- 每个环节至少保留标题行，无新闻时标注"今日暂无重要动态"
- 多来源同一事件时，合并为一条并标注多个链接
- 报告尾部必须附"自检结果"小节（列出13项Rubric的PASS/FAIL + 来源分级统计）
- 来源分级统计必须基于URL域名判定，不依赖display text
- 最末附免责声明
- **不设置"市场动态"等附录**——市场分析违反中立性边界

## 失败处理

| 情况 | 修复 | 兜底 |
|---|---|---|
| 来源链接失效 | 标注"链接待验证" | 保留标题和摘要 |
| 无法确认时间 | 标注"日期待确认" | 只保留日期不保留时分 |
| 无新闻的环节 | 标注"今日暂无重要动态" | 不省略该环节 |
| 搜索无结果 | 切换为备用搜索引擎重试一次 | 标注"该环节信息获取失败" |
| 摘要过长（>100字或≥6句） | 回到Step 5重新压缩，按句数控制 | 兜底保留原文前3句 |
| 信息冲突（多源报道矛盾） | 标注各方说法，注明信息存在分歧 | 不做主观判断 |
| 涉及非公开信息 | 自动跳过，不纳入日报 | 不标注 |
| sources.md 不存在 | 回退至公开新闻源（SEMI/TechInsights/TSMC等） | 正常生成日报 |
| 分类存疑 | 按 classification.md 的存疑仲裁规则确定默认归属 | 归入"综合/其他" |
| A级来源不足30% | 补充搜索权威源（基于URL域名判定） | 标注"今日权威源不足" |
| Rubric循环超5次 | 保留最后一次结果，在自检结果中标注FAIL项 | 正常输出 |
| 未来日期新闻 | 标注"日期异常"，检查是否笔误 | 修正日期或删除该条 |
| 0条新闻（节假日） | 所有环节标注"今日暂无重要动态" | 来源质量检查自动PASS |
| 非交互模式（定时任务） | Step 1使用默认日期范围 | 不等待用户输入 |
| 负面新闻/安全事故（如工厂火灾） | 如实记录事实，标注多方说法 | 不做主观评价，不隐瞒 |
| 争议事件/多源报道矛盾 | 标注各方说法，注明"信息存在分歧" | 不做主观判断，保留各方观点 |
| 未经验证的独家爆料 | 标注"待验证"，不作为独立新闻条目 | 除非有第二独立来源佐证 |

## 边界

- 只汇总公开可访问的新闻来源，不引用付费墙内容。
- 不做投资建议或市场预测。
- 不做技术分析或深度评测——日报是事实汇总，不是分析报告。
- 不按股价涨幅、市值变化等金融指标排序——按重要性（影响范围>技术突破>市场规模>企业动态）排序。
- 时间戳以来源页面的发布时间为准，**72小时判定基于日期差（天数差>3则标注[回顾]）**。
- 不引用社交媒体（微博、Twitter等）未经验证的传言。
- 不翻译外文新闻标题，保留原标题并附中文摘要。非英文外文标题可附中文译名（标注"译"字）。
- **不设置"市场与政策动态"附录**——市场分析违反中立性边界，不应以附录形式绕过。市场分析类内容如需发布，应作为独立报告，不混入日报。

## 反例黑名单

| # | 不要做 | 为什么 | 应该做 |
|---|--------|--------|--------|
| 1 | 省略无新闻的产业链环节 | 破坏日报完整性，用户会误以为遗漏 | 标注"今日暂无重要动态" |
| 2 | 引用社交媒体截图作为来源 | 无法验证真实性，可能是谣言 | 只引用可公开访问的正式新闻源 |
| 3 | 将市场预测/投资建议/技术分析混入日报 | 日报是事实汇总，不是分析报告 | 事实和观点分离；分析类内容作为**独立报告**发布，不混入日报、不以附录形式绕过边界 |
| 4 | 只用单一搜索引擎搜索 | 信息覆盖面窄，容易遗漏重要新闻 | 至少使用中英文双语搜索（1中+1英） |
| 5 | 抄袭/搬运原文全文 | 侵犯版权，日报应提炼摘要 | 摘要控制在3-4个短句（约50-100字），标注原文链接 |
| 6 | 按股价涨幅或市值变化排序新闻 | 金融指标不等于新闻重要性 | 按影响范围>技术突破>市场规模>企业动态排序 |
| 7 | 设置"市场动态"附录绕过中立性边界 | 附录不是规避规则的漏洞 | 市场分析完全不纳入日报，如需发布作为独立报告 |
| 8 | 把软件/SaaS/AI应用塞入材料设备环节 | 不属于芯片产业链 | 按分类判定规则归类，不属于产业链的不纳入 |
| 9 | Rubric只列不执行或笼统声称"已自检通过" | 规则形同虚设 | 门禁制：不通过则修正后重新输出；**自检结果必须显式列出每项PASS/FAIL**；**必须运行校验脚本** |
| 10 | 摘要不压缩直接搬运原文 | 违反50-100字规则，侵犯版权 | 保留四要素(主体+事件+数据+影响)，按句数控制(3-4短句) |
| 11 | 全部使用聚合页来源 | 来源质量低，可信度差 | A级权威源占比≥30%（基于URL域名判定） |
| 12 | **SKILL.md与配套文件(sources/classification/rubric/scripts)不一致** | 模块化架构下文件间引用失效，LLM加载到过时规则 | 修改任何规则时，同步更新所有相关文件 |
| 13 | **来源级别判定依赖display text而非URL域名** | display text可注入A級关键词绕过30%门禁 | 来源级别判定只检查URL域名，不检查display text |
| 14 | **按需加载文件变为可选操作** | LLM可能跳过加载引用文件，使用过时或内置知识 | 每个【强制】加载指令必须执行，不加载则对应Step无法正确完成 |
