# 扩源手册（数据源接入八步 SOP）

- 版本：v1（2026-09-29）· 来源：AIHOT 扩接架构内化（机制拆解见 `delivery/内化_数据源扩接_AIHOT_20260929.md`）
- 定位：把「加一个源」从隐性经验固化为显性流程。现状基线：collector.py 14 个 RSS 子类 + 4 个自定义采集器（SEC EDGAR / AIHOT / 巨潮 / Newsnow），registry.py 49 源网格，discover.py 自主发现层（动态源不走本手册，走 discover 四道验证 + trial/active 生命周期）。
- 纪律：**本手册是流程文档，新增门禁/源属工程冻结范围（至 2026-10-12）**——冻结期内按本手册做「评估与登记」，实现步留冻结期满。

## 八步 SOP

### ① 候选登记（只登记，不实现）
缺口来源三选一：gap_analyzer 网格缺口（segment × type）/ 日报实战缺源（某条重要新闻找不到一手）/ registry.py `status="planned"` 槽位。登记到台账候选行，写明：站名、想补的环节（设计/制造/封测/EDA/材料）、预期 type（ir/news/analysis/filing/data/academic）。

### ② 死源黑名单核对（先查死者，省探测预算）
先核对 `scripts/multi_source/collector.py` 的死源注释块（实测已死，勿接）：TrendForce 旧版 RSS(404，feed_v2 可用)、The Elec(403/502)、AnandTech(关站)、36kr `/feed`、虎嗅 `/rss/0.xml`、Bing News RSS(仅 12 条)。命中即放弃或换端点，新测死的源**当场补进注释块**（带日期）。

### ③ 实测 probe（AIHOT「试抓先行」纪律的手工版）
```bash
# 直连一路 + 走代理一路（国内站走系统代理常被拦——collector _safe_fetch_ex 同款经验）
curl -sS -o /dev/null -w "%{http_code} " <feed_url>
curl -sS --proxy http://127.0.0.1:7897 <feed_url> | head -c 500
```
验收四条：HTTP 200；条目数 ≥10；**文章级直链**（非列表页/跳转链——[G-1] 门禁要求）；pubDate 新鲜（警惕列表缓存日：TrendForce feed_v2 的 pubDate 曾全是列表生成日，引用以文章页日期为准）。

### ④ 定级（人工唯一通道）
tier 口径（registry.py 现役）：0=公司一手 IR/官方公告，1=英文权威直连，2=监管原始文件，3=中文权威，4=聚合线索（B 级仅线索）。A/B 级同录 `rules/rule_registry.yaml`：B 级转载源引用时**须追溯权威原始来源**（ithome 先例）。定级写入 registry 后必须跑 `gen_rules.py` + X7 一致性——这是唯一合法通道，禁止改脚本字面量。

### ⑤ 实现 collector 子类（冻结期满后）
RSS 源 = RSSCollector 子类 ~10 行（模板见下）；非 RSS 站型（JSON 接口/分页列表）写独立 BaseCollector 子类。docstring **必须带实测日期+结果**（哪天测的、200 还是 403、内容形态）——这是本仓库扩源的「配置契约」：死活与形态记录在源声明旁，不留口头记忆。

```python
class XxxCollector(RSSCollector):
    """<中文名>（实测 200 · 2026-MM-DD，N 条全文章级）。补 <环节> 视角。
    registry 定级 X 级（<理由>）。"""
    source_id = "xxx"
    source_name = "Xxx"
    tier = 1
    feed_url = "https://..."
```

### ⑥ registry.py 网格登记
SOURCES 加一行 dict：id / name / tier / type / segments / url / status="active"。跑 `python scripts/multi_source/registry.py` 重建 source_registry.json（gap_analyzer/health 共用）。

### ⑦ 一致性与测试（四件套，缺一不算接完）
1. `gen_rules.py --check` 无漂移；
2. X7 镜像一致性：`check_rules_consistency.py` 全绿（multi_source 模块在镜像范围，改了 collector.py 必须同步 .trae 镜像，Read+Write 逐文件，cmp 复验）；
3. pytest 注册断言：新类必须进 ONLINE_COLLECTORS / PROBE_ENDPOINTS 断言（防 v7 式静默缺失——TrendForce 债的教训）；
4. 真实首采一次：确认产出条目文章级、时效 ≤72h、与既有 seen 账本去重正常。

### ⑧ 台账登记 + 观察期
迭代台账记一行（源/定级/实测数据/接入轮）。观察 3 个运行日 health_check：连续失败按 source_health 既有处置；产出与首采状态看 `python scripts/multi_source/ledger.py --status`（v9 机制版：首采 >30 天自动丢弃 + 30 条封顶已由账本强制，per_day 速率 3 个运行日后自动可算——人工抽查 ≤72h 时效仍保留，防「feed 级日期可信但内容旧」的漏网形态）。

## 已知坑清单（实测累积，接源前过一遍）

- **编码**：部分中文源 GBK 编码，utf-8 直解会乱码（cleaner 容差通配仅限小范围）。
- **命名空间**：RDF/RSS1.0 日期在 `dc:date`（Nikkei 实测），解析须按本地名兼容。
- **代理**：国内站走系统代理被拦 → 双路实测必须含 no_proxy 路（`_safe_fetch_ex` 同款）。
- **301 降级**：http 降级链（tomshardware `/feeds/all` 301 到 http 的 feeds.xml）会被 https 门禁拦到零产出，用 https 直出端点。
- **JS 壳**：财联社/ithome 快讯页是 JS 壳（端点 404/签名墙），无 RSS 的中文权威站现状靠转载链（B 级）或 AIHOT 聚合补——web_list 选择器适配器是潜在解（真差距③，与 newsnow/RSSHub 决策合并拍板）。
- **缓存日 pubDate**：feed 级 pubDate 可能是列表生成日而非文章日（TrendForce），引用以文章页日期为准。

## 一句话

扩源的成本不在写采集器（~10 行），而在**验证与定级的纪律**——八步一步不少，六纪律条条落点，接进来的才是资产，跳步接进来的是事故。
