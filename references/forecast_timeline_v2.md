## 2. 已验证判断的方法论沉淀（可复用）

从 3 条完全一致的判断中提炼出的**成立依据**与可迁移规则：

### M1. 「已公告时点 + 公司一手信源」是时点零误差的充分条件
- 证据：中芯说明会（公司官宣日历）、BIS 生效（联邦公报载明日期）、英伟达财报（公司官宣）——3 条时点全部精准。
- 可复用规则：**前瞻时点锚必须取自"公司官宣/官方公报"的直接日期，不得由第三方推算。** 若找不到一手日期，确定性必须降档。

### M2. 「方向判断」比「数值判断」更先兑现
- 证据：5 条已验判断中，方向性判断（管制收紧/需求强劲/会谈低产出）5/5 正确；数值与时点各错 1 次。
- 可复用规则：把认知资源优先投入"方向+传导链"判断；数值预测一律挂区间或剧本，不点单值。

### M3. 多剧本并行让"被打脸"变成收益
- 证据：中芯条目 3 剧本首验——真趋势印证、炒作剧本被打脸恰好证明主判断（稼动率高企）正确、被绕开剧本被淘汰。
- 可复用规则：每个高重要度前瞻挂 2-3 个互斥剧本；**"炒作剧本被打脸"是主判断正确的确认信号**（与 STANCE_HOPEFUL 语义一致）；被淘汰剧本不得复活，除非出现新的可验证证据。

### M4. 校准器的阈值告警是有效雷达
- 证据：M3 首轮即抓出"高确定性偏差率 33% 超阈值"，样本恰好锁定两条失败模式（见第 3 节）——雷达没漏报也没误报。
- 可复用规则：每期日报必跑校准器；连续 2 期同档位超阈值才触发 rubric 修订（单期超阈值只记录观察，防小样本过拟合——当前 n=5，本轮修订即按此例执行）。

## 3. 偏差归因（逐条，四类归因框架）

偏差条目按四类原因拆解：**信息不足 / 假设有误 / 时间尺度设定不当 / 外部变量干扰**。

### 3.1 20260814-uscn-talk（中美会谈）——「⚠️ 信号偏弱」
- **主因：假设有误（确定性语义混淆）**。把"会谈已宣布召开"（确实高确定）与"会谈将产出半导体专项成果"（不可预测，从未公告）混在同一预测对象里。前瞻原文只判"时点是否官宣"，但判断语句里隐含了对成果的期待。
- **次因：外部变量干扰**。BIS 年报（执法 18 倍/列名停摆）同期披露，使会谈的信号价值被稀释——单事件的信息含量取决于同期信息环境，登记时未预估。
- **修正动作**：
  1. rubric 补反例：**"会谈/峰会/对话类事件，前瞻对象只能是'是否如期举行'；任何成果预期一律移入『观察点』，不作为验证对象"**（已写入第 4 节修订版确定性标准）。
  2. 该条确定性档位在语义上应记为"高确定（举行）/不可判（成果）"二元结构，登记时拆开。

### 3.2 20260817-tsmc-rev（台积电 7 月营收）——「⚠️ 时点提前 8 天」
- **主因：时间尺度设定不当（惯例日错配）**。前瞻时点锚参照了"财报日历"（季度业绩 8-18 前后），但月度营收公告遵循另一惯例——每月 10 日前后。8-18 是上期登记时的随手推算，违反了方法论 M1（未回到公司一手日历核对）。
- **修正动作**：
  1. 建立**「公告类型 → 惯例日」映射表**（已生效，见下）；
  2. 台积电 8 月营收前瞻（20260828-tsmc-aug）已按修正后口径登记为 9-10。
- **映射表（首版，随验证持续修订）**：
  | 公告类型 | 惯例日 | 例证 |
  |---------|--------|------|
  | 台积电月度营收 | 每月 10 日前后 | 7 月营收 8-10 公布（SEC 6-K） |
  | 季度法说会/财报 | 季末后 2-4 周，以公司官宣为准 | 英伟达 8-26、中芯 8-14 |
  | 法规生效日 | 联邦公报载明日 + 缓冲期推算 | BIS 8-15 / 10-14 |
  | 产品发布会 | 公司官宣邀请函日 | 苹果 9-9 |

### 3.3 未验证条目的归因预告（防患于未然）
- **20260828-tsmc-aug**：唯一风险是"环比基数效应"——7 月环比+5.6% 高基数下 8 月环比转负仍属正常季节波动，剧本「被绕开」已把"增速回落但结构性"列为合法结局，防止单月读数误伤主判断。
- **20260828-apple-event / zyrf-price**：信息基本齐备（已官宣），主要不确定性在**验证判据的事前定义**——已分别在条目 when_judged 中写明判据（存储基础容量是否上移 / 下游是否跟进调价），避免事后"怎么解释都对"。
- **20260828-bis-eda-gaafet**：距离 10-14 尚有 47 天，期间存在**外部变量**（美方追加细则或豁免、中方反制清单扩围）可能改变验证语境——已在判断要点中列明这两个变量，届时一并核对。

### 3.4 格局时间轴（1-3 年 / 3-5 年）的固有归因：信息不足
- 远期节点（如"HBM 缺口延续至 2027-2028""长鑫份额向 17% 爬升"）不可事件化验证，**信息不足是结构性的、不是缺陷**。处理方式不是假装能验证，而是：**降格为"期度检查点"+ 每条配可证伪信号（falsifier）**，按季度核对、按证据修正。见第 4 节 v2.0 时间轴。

## 5. 循环机制（确立为常设流程）

**预测 → 验证 → 归因 → 修正** 四步固化为固定节拍：

1. **预测**（每期日报）：新前瞻必含 ①公告类型惯例日核对 ②事前判据 ③高重要度挂互斥剧本。
2. **验证**（事件到期后 48h 内）：跑 `forecast_tracker.py verify`，剧本逐个打分；逾期未验条目在下一期日报「前瞻兑现回顾」强制列出（当前 0 条逾期）。
3. **归因**（偏差条目 100% 归因）：按四类框架（信息不足/假设有误/时间尺度/外部变量）写入 verified_note；单条归因必须引用证据（URL/数据），禁止"感觉偏差"。
4. **修正**（累积触发）：单期超阈值→记录观察；连续 2 期同档位超阈值→rubric 修订；每 4 期或每月做一次本文档式全量审计。

**自动化挂接（已运行）**：M3 校准器（偏差率+剧本命中率）→ M4 规则自生长 → M5 反写 SKILL.md（抗遗忘）→ M6 计数（auto_streak，里程碑 30）。本审计的教训已同步沉淀至 SKILL.md 锚点段（人工补充块，2026-08-28）。
