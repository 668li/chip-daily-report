# 市场调研：个性化日报产品形态（2026-10-01）

> **本文只回答一个问题**：勇谚设想的「日报产品开机问身份 → 按想要的章节 → 自动接入该领域数据源 → 需要账号就引导登录 → 每天自动查取成稿」，别人走到哪一步了？
> **性质**：纯文档，零代码零配置，落在冻结纪律（工程冻结至 2026-10-12）允许的「评估与登记」范围内。
> **本文不是施工方案**，方向由勇谚拍板后才动。

## 〇、一句话结论

**五格里没有一格被完整走过，但每一格都有别人的半成品；最值钱的是「自动接源」与「结构可定制」两格的交叉——全市场 41 个商业产品 + 31 个开源项目里，一个都没占住。** 而「需要账号就让他登」这条反而是今天最成熟的一段（Playwright 持久化 profile 已是一等公民支持），真正的空白在「教读者看懂」这一层。

### 1.2 工具失败披露（`AgentChat-WebSubAgent` 未参与）

按你的指定，商业产品这路先走了 `AgentChat-WebSubAgent`，**三次执行全部失败，web AI 未参与任何一步**：

| run_id | 模式 | exit | 失败原因 |
|---|---|---|---|
| `ac-6abdca79c4cb9a35d29f8a04` | search | 2 | `no_cdp`（kimi）→ `skipped_no_cdp`（qwen） |
| `ac-6abdcafedb07e4870f3724b7` | search | 2 | 同上 |
| `ac-6abdcbf559cc6b4c65769e0e` | search | 2 | 同上（已带正确 CDP_PORT） |

**根因已精确定位，不在 skill 逻辑层，在 Playwright ↔ Chrome 层**：

```
browserType.connectOverCDP: Timeout 25000ms exceeded.
  - <ws preparing>  retrieving websocket url from http://127.0.0.1:9223   ✅
  - <ws connecting> ws://127.0.0.1:9223/devtools/browser/4728bf43-…     ✅
  - <ws connected> ws://127.0.0.1:9223/devtools/browser/4728bf43-…      ✅ 卡在这里
```

裸跑 `playwright-core@1.61.1` 的 `connectOverCDP`（不经 OneWeb）打这台 `Chrome/154.0.8037.58` **同样 25s 超时**，证明与 skill 逻辑无关。CDP 的 HTTP 端点与 ws 均正常（`/json/version` 返回、4 个 provider 页面在线：Kimi / 千问 / Gemini），**ws 连上后握手永远不完成**——判断是 Playwright 1.61 与 Chrome 154 的协议/target 类型不兼容（该实例存在 `browser_ui`、`shared_worker` 等新 target 类型）。

**排查中纠正的一个误判**：`--doctor` 报「CDP reachable」但实际运行报 `no_cdp`，一度指向端口不一致（OneWeb 默认 9222、doctor 报 9223）。查 `.env` 后确认 `CDP_PORT=9223` 就是 skill 的**专用调试 Chrome**（profile `~/.chrome-debug-profile`，与日常浏览器隔离），我手动覆盖 `CDP_PORT=9223` 等于没改，**无副作用**。三次失败是同一原因。

**未做的动作**：skill 自带修复手段是 `scripts/start-chrome.ps1` 重启专用调试 Chrome。判断这是版本不兼容而非 Chrome 卡死，**重启大概率无效且会关掉你已登录的 provider 会话**，故不做。若要修，需升级该 skill 的 `playwright-core`（属改动你的 skill 环境，未经拍板不动）。

## 三、空白在哪（四条，按价值排序）

1. **【最值钱】自动接源 × 章节结构可定制 的交叉格——41 个商业产品 + 31 个开源项目，零占据。** 越线的（ClarityBriefs / Kompyte）输出结构锁死；结构可定制的（Elicit / Feedly Automated Newsletter）源要么靠用户已有订阅、要么锁在人造本体论里。
2. **【第二】质量校验做成「用户可配置的字段」而非「厂商隐形逻辑」**——全市场只有 Feedly 的 **Org Profile > Tradecraft** 一家做到（官方原文：*"Instructions for **citing sources, separating facts from assessments, stating confidence, and identifying information gaps**"*），且 2026-09-29 才发布、挂在威胁情报线、面向安全分析师。**没有消费级或专业领域日报产品把 A/B 信源分级、双源交叉验证、置信度、信息缺口暴露给用户。**
3. **【第三】教学层——在「专业领域日报」这个品类里 100% 空白。** 41 个产品里只有 2–3 个有任何教学成分（Exploding Topics 的增长归因拆解做得最好、Morning Brew 杂志式短文、TLDR 轻微）。**而竞品的优化方向是把摘要做得更短**（Nudget 的 verbose/compact/links-only 三档、Readless 主打「85% 阅读时间节省」）——**方向与我们相反**。
4. **【第四】跨源「事件聚簇」做成用户可见的一等公民**——只有 Ground News（免费、政治新闻）和 AlphaSense（天价、买方）做了。Adviserry 把它叫 cross-panel insights 收 $49/mo，说明有人信它值钱。

**必须诚实指出一个「假空白」**：用户描述领域 → **实时**抓全网，通用 agent（ChatGPT / Perplexity / Claude）每次运行自己决定读哪些站，早就做到了。**不能把「能读全网」当卖点。** 卖点必须押在**「持久化 + 可溯源可分级 + 结构可定制 + 教学层」四件事绑在一起**——通用 agent 这四项一项都不做（它们即用即弃、无信源档案、无分级）。

## 四、「需要账号就让他登」——这条反而最成熟

### 4.1 成熟实现（直接用，不要自己写）

1. **Playwright 持久化上下文**：官方一等公民支持 `launchPersistentContext(userDataDir)` 或 `storageState`（login 一次导出 JSON，之后复用）。
2. **OpenClaw 的三种 browser profile**（当前工程化最完整）：`openclaw`（托管持久目录，**你自己在里面手登一次**，之后无人值守复用）/ `user`（Chrome DevTools MCP 直连真实已登录 Chrome，需人在电脑前点一次授权）/ `chrome`（扩展驱动真实已登录 tab，人不在也行）。
3. **云浏览器** Browserbase + Stagehand（需 7×24 才划算）。

### 4.2 但「永久」两个字不成立——真正的工程缺口在这

Playwright 官方文档自己写着：*"We recommend to authenticate by manually running the auth.setup.ts from time to time, whenever existing authentication expires."*

所以缺的不是「怎么做持久化」，而是**失效检测 + 重登引导 + 重登 UX**——今天没有现成方案。

**另一条应写进设计文档的经验**（OpenClaw 官方）：*"Automated logins often trigger anti-bot defenses and can lock the account."* → **引导用户手工登录一次不只是最省事，它同时是最不容易被封号的**；自动填表登录是风险源，不是解法。

### 4.3 授权市场的 2026 现状（实测/核实）

| 平台 | 现状 | 对我们的含义 |
|---|---|---|
| **X/Twitter** | 已彻底改按量付费：Posts Read $0.005/条、**无免费层**、月上限 300 万条。Feedly 官方文档自认接 X「typically costs **$100–200 per month**」 | 每天 200 条 ≈ **$30/月/主题**，不是自用零成本路径 |
| **Reddit** | 2025-11-11 起强制 Responsible Builder 审批，自助申请已关，匿名 JSON 实测 403 | 不能作为「一键授权」新手路径 |
| **LinkedIn** | Partner Program 审批制，官方 API 本就不含内容抓取，未授权 401 | 排除 |
| **Gmail / Notion / Slack** | OAuth 成熟，但需平台审核；Notion 官方 MCP 实测 401（= 服务在、OAuth 在等） | 唯一「干净」的路 |
| **MCP 生态** | 注册表约 1 万条，但**实测 3 个条目对应仓库 404**（`io.github.CyberMax-tools/rss-feed-finder`、`com.rssatlas/rss-atlas`、`ai.agentic-news/mcp`） | **不能当可信目录直接消费**，任何基于注册表发现的方案必须先做仓库存活校验 |
| 公众号转 RSS | wewe-rss 已归档、feeddd 已死、Wechat2RSS 无许可证且收费 | 中文账号类源**没有可依赖的开源地基**，要自研且持续作战 |

**Cookie 复用的法律红线（WorkOS 2026-03-31 分析）**：自用场景「practical and often sufficient」，但明确指出**无法平移到 B2B**——你无法区分 agent 流量与人类流量、无法单独吊销 agent 权限、审计日志失去意义。**我们现在是自用，这条路可行；如果将来要给别人用，它从「可行」直接变成「不可交付」。**

## 六、这波产品的普遍弱点（附证据）

1. **噪音太大——厂商自己都承认。** Feedly 专门写文档教用户「如何限制每周推多少篇」来降噪，并自认默认行为「drastically reduce noise」；另有整套 Mute Filters。**一个需要专门写文档教用户闭嘴的产品，说明默认体验是吵的。**
2. **摘要太浅、不溯源——品类原罪。** 41 个产品里明确有逐条引用的只有 Kagi News / Readless / Perplexity / Elicit / AlphaSense 五个。**中文字段溯源几乎为零**——同花顺 i问财页脚只有「内容由AI生成，请仔细甄别」。TLDR 官方 2025-12 发布过一条《TLDR Responds to Your Complaints and Criticism》视频，说明批评是系统性的。
3. **推荐越来越窄 / 回音壁。** Ground News 把 **Blindspot**（专推你「没看到的」故事）当核心功能，就是在拿产品功能打这个问题——但**只在政治新闻里做，专业领域日报没人做**。
4. **「只是把你已有订阅重新组织一遍」——被用户点破也被厂商承认。** 这正是 Readless / Nudget / Adviserry / Gemini Daily Brief 整类的定义。Adviserry 的比喻很准：open-internet 型简报的个性化「**tuned to your sign, written for everyone born in your month**」。**这是我们最该警惕的天花板——做成「从已有订阅生成」，就永远只是 Readless 的更贵版本。**
5. **重复付费无感。** Readless 要花一整篇文章向用户解释「免费额度到底怎么算」；分类页里最扎眼的一句是同时订阅三个 AI 日报的用户面对「一份摘要告诉你另外两个都说了什么，而他们三个讲的是同一件事」。**中国市场更严重**：同花顺/慧博/萝卜投研/Wind 同时订阅是常态，但没有产品告诉用户「你已经重复付了」。
6. **品类死亡率极高（最硬的信号）。** **5am AI**：站点今日返回 `DEPLOYMENT_NOT_FOUND`，域名已易主。**Huxe**：NotebookLM 团队出身、做 AI 音频日报、有关注话题的「live stations」（几乎就是我们的产品描述），**2026 年 5 月关停、下架、删库**。HN 上「AI daily briefing」相关 Show HN 是一串 2–5 分零反馈项目。
   > **这个品类不是没人做，是做的人留不下。** 留不下的原因几乎都是同一个——**没有形成「每天必须打开」的理由。摘要不改变任何决策，日报就不值得读。**
7. **只适合技术人 / 只适合不懂技术的人，中间那格没人。** Inoreader 自我定位就是「built especially for power users」，明确把普通用户排除；Ground News / Morning Brew 那一端完全不碰专业领域深度。**「懂业务但不想配 RSS 的从业者」是空位。**
8. **英文/本地化断层。** Feedly AI 明确只处理英文。**中文专业领域日报的竞争密度明显低于英文市场——这是窗口，不是蓝海的保证。**

## 七、给方向决策的三句话

1. **不要把「能自动发现信源」当卖点**——Kompyte / ClarityBriefs / Contify 已越线，通用 agent 更是随时能读全网。**卖点必须是「自动发现 + 结构可定制 + 每条可溯源分级 + 教学层」四件事绑在一起卖**，因为这四件事的**任意两两组合**市场上都找不到第二个完整样本。
2. **「教学层」是最便宜的差异化。** 我们已经在做了，全市场 41 个产品里 0–3 个有；且竞品的优化方向是**把摘要做得更短**，方向与我们相反。当所有人都在卷「更短」，「讲清楚为什么」就是一个没人抢的位置。
3. **品类会死人，护城河不在内容在习惯。** 5am 与 Huxe 已死，HN 上几十个 Show HN 零反馈。日报结构里「今日一课」这一节，很可能是唯一能让人**明天还想打开**的东西——**摘要不留人，课留人**。
