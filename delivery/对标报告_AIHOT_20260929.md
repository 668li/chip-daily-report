# 对标报告：AIHOT 开源框架（KKKKhazix/AIHOT）

- 日期：2026-09-29
- 对象：https://github.com/KKKKhazix/AIHOT （MIT，341★/106 fork，线上站 aihot.news 的全量代码快照）
- 定位：一个「自己找热点、自己写日报」的通用热点站框架；技术栈 Node.js 24 + TypeScript + Fastify + PostgreSQL + pg-boss + Docker；作者设计师出身、代码与 AI 共同重写
- 调研方式与置信度：子代理精读仓库约 45 个核心文件原文（含全部 26 个提示词、editorial/events/sources 核心模块、数据库迁移、全部 docs）；本会话抽查 `industry/selection.ts` 原文确认双评分与门槛数值、实测线上 API 200。未逐行复核前端与全部 35 个迁移，机制级结论可信、行级细节以原文为准
- 关系澄清：本仓库 ≠ 本地已装的 `aihot` skill（那是其线上站 aihot.virxact.com 的查询技能，同一家的消费端）

## 一、设计哲学（5 条）

1. **判断权与执行权分离**：模型只负责理解与措辞（打分、归组、写标题），代码负责事实与规则（实体守卫、长度压缩、状态机、时间线）。模型输出是「建议」，过不了确定性闸门就不见读者——与我们「门禁对不上不出版」同魂。
2. **KnowHow 与引擎分离**：`industry/` 行业包（sources.json/prompts/selection.ts/taxonomy）装全部行业知识，换行业=编辑文本不改代码；提示词版本=内容 SHA256 前 10 位，每次模型调用回执记录版本——「哪句话产生了哪个结果」可追溯。
3. **付费调用可复现/可熔断/可审计**：logical_key 幂等（同输入复用已付结果）、先存响应再写业务、unknown 协议（超时不自动重发，防重复花钱）、advisory-lock 预算熔断。对零付费管线的我们暂不适用，但对任何 AI+付费 API 管线是范本。
4. **时间线的诚实性**：`published_at`（可信）与 `published_at_claim`（声称）分列；发现时原文已发布超 48h → 按原文时间归档，不进「今天」、不建事件、不算热度；抓取落后的信源单独分组统计，防「某源没抓到」被误判为「热度变化」。
5. **按事件而非按文章组织世界**：fact（一次发生）∈ story（事件）；多源印证被制度化——热度=独立参与者计数（48h 窗口 24h 半衰），日报每个事件只取一条代表报道。

## 二、核心机制拆解（值得记的硬细节）

- **评分宪法**（`prompts/selection-score.md`，109 行全仓库最核心 KnowHow）：五轴 0-10（实质份量/信息增量/证据强度/共振面/可用性）× 按内容类型加权（每型和为 10，合成 0-100）；噪声带硬上限（例行小版本 sig≤3、营销软文 sig≤2）；「事件口径校正」纠正模型把稿件长短当价值的系统性偏差。
- **盲评**：打分输入只有发布时间+原标题+正文，**故意不给信源名与分级**（「不要把大厂名校长正文当自动加分项」）。门槛反而按信源分级区分：T1 官方一手 60 / T1.5 准官方 65 / T2 媒体个人 76——分级越低门槛越高（原文已抽查核实）。
- **双评分**：同提示词 temperature 1 串行独立打两次，两次之和 ≥ 2×门槛才精选（平均分只用于展示）——「置信度稳定跨越门槛才入选」，暴露提示词模糊地带。
- **聚簇**：embedding 召回（14 天窗、余弦≥0.6、top10）→ 批量三方判定（SAME_OCCURRENCE/SAME_STORY/UNRELATED）→ 相似度<0.85 的合并**换一家模型复核**；故事合并双向互换再判一次；人工判定永远赢（写库前行锁内再查）。
- **判重**：identity_key 唯一约束（URL 规范化：去 www/去 hash/去 30+ 跟踪参数/参数排序；公众号只留 4 参数）+ content_hash 修订（同哈希跳过、历史哈希复现不算新料、乱码容差通配）。
- **防幻觉三层**：提示词 9 条（相对时间照抄绝不换算年份、排他性表述须原文明确、不得强化语气范围）→ **IdentityGuard 代码守卫**（正文允许集之外的公司名出现在产出标题 → 标题回退/摘要整体置空并落库诊断）→ 确定性后处理（超长摘要按句边界无模型裁剪）。
- **信源运维**：6 类型（RSS/网页列表/JSON/X/公众号/脚本推送）；抓取间隔自适应=近 7 天日均产出→目标间隔夹在 [15, 类型上限]，失败指数退避且**预算熔断不计入失败**。
- **SelectBench 校准**（`scripts/eval-selection.ts`）：金标 jsonl（select/reject/either 三态）→ 跑真实管线 → accuracy/precision/recall/F1 + **门槛 40-90 步长 2 全扫描**；development/holdout 分集防过拟合；方法论=**先改标准再动门槛**（「门槛只能整体移动，解决不了哪一类判错了」）。
- **告警三级**：now（读者已受影响，恢复要报平安）/today（钱有风险）/digest（每日汇总）；每条四要素=读者看到什么/会不会自愈/站长要做什么/给 AI 的排查线索。

## 三、逐机制对照（它有 ↔ 我们有）

|---|---|---|
| KnowHow/引擎分离（industry/ 包） | rule_registry.yaml + gen_rules + X7 + references/ | **已同构**，互为印证 |

| 盲评防光环 | gate G3 publisher_domain 官方一手域加分（反方向：显式给权威加权） | 目标不同不冲突：我们管供给质量，它管分数虚高 |

## 四、护城河判决更新

AIHOT 是「事实策展引擎」：**没有**推演可问责、没有批评代谢、没有教学层（它的「理解层」是给 Agent 的 API，不是给人上课）、没有数字级声明对账（它防「写错公司」，我们防「数字对不上原文不出版」——后者更狠）。独占项全部不动摇；诚实性工程仍领先。它的强项在**工程完成度与选稿校准闭环**——单人项目做到 341★，值得敬畏的是纪律而非堆料。

## 五、行动建议

**冻结期内即可做**（写作纪律+供给已解冻，不需新校验器）：
1. SKILL/references 吸收 5 条写作纪律：矛盾显式标注；相对时间照抄绝不换算；排他性表述须原文明确；不得强化语气与范围；标题保型（How/Why 类不得改写成「X 发布 Y」）。
2. **供给评估**：aihot.virxact.com API 实测 200 免 key（本日已验证），返回中文标题/摘要/score/reason/original 直链，源重合度高（IT之家）——可评估接入 discover 作「AI×芯片交叉」发现引擎（第 3 期 AMD 收购 World Labs、英伟达回购正是它的主场）。**注意**：只当发现层候选源，不当引用源——摘要出自它的引擎，承重对账仍须抓 original 原文。
3. 心跳/告警消息升级为四要素格式+恢复报平安。

**冻结期满 2026-10-12 首批**（新校验器/管线侧）：
4. 金标样本集：人工标注 100-200 条候选（select/reject/either）——标注是数据准备，可提前做。
5. SelectBench 式 eval：对 discover 相关性 0.30 与 gate conf_min 跑 P/R/F1+门槛扫描，替代手调，与债⑧阈值族重构合并执行。
6. 承重实体守卫：条目标题中公司名须在来源原文出现（补 validate_claims 只对数字的空档）——芯片公司太散，只做承重条目窄守卫，不移植全量词典。
7. 抓取频率自适应算法 + 热度「公平性修正」思想并入管线侧重构。

**明确不抄**：PostgreSQL/pg-boss 引擎、回执/预算/幂等（零付费）、RSS/MCP 输出层、模型榜、向量聚簇（embedding 付费且日活规模不需要）、全量公司词典。

## 六、一句话总结

AIHOT 用工程纪律证明了「多源印证 + 可校准选稿 + 防幻觉守卫」可以全部机制化；我们在这三条上分别已有同构物、最大空白在**选稿校准闭环**（金标+门槛扫描），最便宜的即时收益是它的**写作纪律条款**（已解冻）与**免费 API 交叉源**（实测可用）。
