- 日期：2026-09-29（AIHOT 对标落地轮的机制深化，聚焦单一问题：**扩源的架构是什么**）
- 对象：KKKKhazix/AIHOT 本地克隆（Temp/aihot，HEAD 589f79e）——本轮新精读 `packages/backend/src/sources/` 全模块（collect/config-keys/rss/web-list/json-list/mp/x/types，~2300 行）+ `ingest/items.ts` + `admin/sources.ts`（previewSource）+ `docs/sources.md`/`docs/customize.md` + `industry/sources.json`

## 一、全景一句话

**扩源 = 往后台/JSON 里加一条数据，不改一行代码。** 全部扩源知识在数据声明（kind+config+tier+参与方式）与六个通用适配器里；引擎只认声明。`docs/customize.md` 的承诺是：把 AI 站换成法律/黄金站，「要改的东西几乎都在 industry/ 一个文件夹里，代码基本不用动」。

## 二、源声明 = 一条 JSON（零代码扩源的第一层）

`industry/sources.json` 18 个示范源（首启导入一次，已存在不覆盖），之后全在后台「信源」页增删改。每源字段：

| 字段 | 语义 | 内化点 |
|---|---|---|
| `kind` | 六选一适配器 | 决定 config 契约（见下） |
| `config` | 该 kind 的参数 | **白名单校验**（第四节） |
| `tier` | T1 官方一手 / T1_5 准官方 / T2 媒体个人 / EXCLUDE_MP | 入选门槛随分级（60/65/76） |
| `participation_mode` | `editorial` 进精选 / `hot_signal` 只作热度证据 / `isolated` 不进任何公开页 | **参与度三档旋钮**：新源可先 isolated 观察 |
| `first_party` + `owner_entity_id` | 是否当事方自述 + 归属实体 | 事件页优先展示一手报道 |
| `interval_minutes` | 每源独立抓取间隔 | 每日自适应重算（第六节） |
| `site_fulltext` / `syndicate_fulltext` | 站内/RSS 能否带全文，**默认都关** | 版权纪律：抓得到≠可展示 |
| `cursor` / `fail_count` | 游标 + 连败计数（运行时） | 状态机（第五节） |

后台信源页能力：新建、**试抓一次看看抓到什么**（`previewSource`：抓但不落库）、改频率、启停、看失败原因和最近条目——扩源的成本被压到「填表→试抓→看结果」三步。

## 三、六类适配器矩阵（扩大接入的第二层：任意站型都有口子）

| kind | 适用 | 准入成本 | 关键机制 |
|---|---|---|---|
| `rss` | 有 RSS/Atom 的一切 | 免 key | ETag validator（304 不重复处理）、分类过滤 |
| `web_list` | **没有 RSS 的网页列表** | 写 CSS 选择器 | parseMode: html / markdown（经 Jina 渲染，按次计费）/ docusaurus_changelog；`detail` 配置抓详情页补齐缺失的日期/标题/摘要；allow/denyUrlPrefixes 收窄范围 |
| `json_list` | JSON 接口（GitHub Releases 等） | 写字段路径 | itemsPath/titlePaths/publishedAtPath/urlTemplate |
| `x_search` | X 账号 | SocialData key 计费 | 普通账号**自动合并成分片搜索**省请求数（第九节） |
| `mp_account` | 微信公众号 | 极致了 key 计费 | ghid，正文一并取回 |
| `external` | 自己写的爬虫脚本 | INGEST_TOKEN | POST 推送，走与普通采集**完全相同**的判重/精选/归组（第八节） |

这六类的意义：**RSS 覆盖不到的站（无 RSS 的新闻页、更新日志、X、公众号），都有现成口子**——web_list 用选择器把「任意网站」变成源，external 把「自写爬虫」变成源，且都不碰引擎代码。

## 四、扩源安全带：配置契约响失败（第三层：防静默垃圾）

`config-keys.ts` 是每 kind 的配置白名单（含嵌套键与枚举值校验）。填了不认识的配置项：**保存被拒绝、抓取直接失败并在后台显示原因**——绝不悄悄退回通用解析。代码注释写明理由：不认识的键若被忽略，会「静默退回通用解析（菜单和句子碎片当文章、日期永远找不到）」。

> 内化点：扩源最常见的死法不是抓不到，而是**抓到垃圾却不自知**。AIHOT 把「配置漂移」从静默降级改成响失败。我方对应物：collector 是类属性无 config 漂移面（结构不同不适用），但「死源黑名单注释+实测日期 docstring」承担同一职责（见手册）。

## 五、采集运行时状态机（collect.ts，扩源的运维底盘）

- **游标续传**：失败不推进 cursor，下次从同处继续；RSS 用 ETag/validator，X 用 lastTweetId+backlog。
- **失败退避**：`LEAST(interval_minutes × (fail_count+2), 360)`——连败拉长间隔至多 6h；fail_count≥5 → health=failing（之前是 degraded）；**预算熔断不计入失败**（那是钱的问题不是源的问题，只等 15 分钟）。
- **首采限量+归档**：新源第一次抓取默认只收 30 条（`initialBackfillLimit`，示范源配 8）、时间窗 12 个月（`initialBackfillMonths`），全部打 `first-import` 标记——**不进「今天」、不推送、不算热度**。
- **单次上限**：MAX_ITEMS_PER_RUN=60；跑内 identity_key 去重（同页 featured+列表双份只存第一份）。
- **detail 补齐带预算**：只为没见过的条目抓详情页，maxFetches 限量，只补 listing 缺的字段。
- **审计**：每次抓取写 fetch_runs（status/found/new_count/error），后台可见「失败原因和最近的条目」。

## 六、抓取频率自适应（每日 04:20，adaptIntervals）

```
perDay = 近7天产出条数(排除 backfill) / 7
target = clamp( 1440 / (perDay × 3),  min,  max )
min: 免费源 15 分钟（经 Jina 付费渲染的 60）
max: 免费 60 / 付费(X、Jina) 120 / hot_signal 180 分钟
X 分片账号固定按参与方式：editorial 30 分钟、hot_signal 60 分钟
```

语义：**每条新文平均被查到 3 次**（1440/(perDay×3)）——忙源自动加密、闲源自动放松、产出为零的源落到 max 档待命。这就是对标报告「抓取频率自适应，算法可直接抄」的原文。

## 七、旧文不刷屏（全入口共用的时间线规则）

首次发现时原文已发布超 48h 的资料、新信源首采的存量条目、显式标记的回灌推送——**一律按原文时间归档：不进「今天」、不推送**。这条规则 rss/web_list/json_list/x/公众号/external 六个入口共用，防止任何一次性导入把历史内容刷成新闻。配合 `published_at`（可信）与 `published_at_claim`（声称）分列。

## 八、外部推送通道（第 7 个口子：自写爬虫即插即用）

`POST /api/ingest/items`（Bearer INGEST_TOKEN ≥16 位，未设置一律 401）：50 条/请求、每客户端 10 次/分钟；缺 title/url 的条目跳过、同请求内 URL 去重。**关键安全设计：sourceId 不存在时自动建源，但默认 `isolated`（不进任何公开页面）+ 标签 `ingest:auto-created`**——运维人工把它升成 editorial 才会对读者可见。`raw._aihot.backfill=true` 显式声明回灌。所有 ingest 写 ingest_events 审计。

> 内化点：扩源的最后一个口子是「体系外的内容也有受控入口」——但默认隔离，人工放行。**先隔离后升格**是外部内容接入的标准动作。

## 九、X 分片（扩到数百个付费账号时的成本工程）

几百个 X 账号若逐个查询，SocialData 按请求数计费会爆炸。AIHOT 把可分片账号（`from:xxx` 型 Latest 搜索）合并成**一次搜索**：按 screen_name 把推文归属回各账号，每账号保留自己的 cursor/健康/fetch_run；搜索水位取各账号 `coveredTo` 的最小值（最后成功时间往前推 10 分钟容迟到）；一次读不完的深度翻页存进各账号 cursor.xBacklog 跨次续读。editorial 账号每 30 分钟一读、hot_signal 每小时。**扩容与成本解耦**的范本（我方无付费 X 源，不抄，记录思想）。

## 十一、内化判决

1. **三个真差距**（按 ROI 排序，全部登记冻结期满 2026-10-12）：
   - ①**首采限量+按原文时间归档**（collector 层）——旧闻事故的机制级解，成本最低收益最直接；
   - ②**自适应间隔公式**（perDay→clamp，含「付费源更懒、免费源可勤」维度——我方全免费源可简化为 perDay→[15,60]）；
   - ③**web_list 型适配器**（CSS 选择器抓无 RSS 页面）——中文权威站直链化的第三条路（newsnow 自部署 vs RSSHub 决策的合并选项，拍板时一起定）。
2. **一个我方独有**：自主发现层。他的扩源哲学是「人填表+六类口子接住一切」；我方是「引擎自己找源+人工定级收编」。两条路线不冲突——发现层产候选、手册八步收编，合并后 = **发现自动化 + 接入纪律化**，这是对标之后我方扩源的完整形态。
3. **不抄清单**：external HTTP 推送 API（单人项目）、X 分片（无付费源）、后台信源管理 UI（无多用户）、PostgreSQL/pg-boss 调度（零付费 Python 管线）。
4. **落地物**：`references/扩源手册.md`——把「加一个源」从隐性经验固化为八步 SOP，吸收 AIHOT 六纪律（试抓先行/首采限量/旧文规则/参与方式/契约响失败/频率自适应），附 RSS 子类模板、死源黑名单与实测坑清单。

## 十二、一句话总结

AIHOT 的扩源不是「会很多爬虫」，而是**把源声明做成数据、把任意站型收进六个适配器、把每次接入关进游标/限量/隔离的安全带里**——扩得快是因为每一步都便宜且响失败；我方已有他没有的自动发现，补上首采限量与 web_list 口子后，扩源能力完整反超。
