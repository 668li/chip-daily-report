# 读者画像 schema v1 · 设计稿（2026-10-01）

> 定位：框架化第一步图纸之一。把 SKILL.md 里"微电子大二勇谚"这层人设从硬编码语义变成
> 可配置结构（reader.yaml），是 D 档抽取的前置设计，也是同类框架（AIHOT 等）没有的器官。
> 性质：**纯设计稿，零代码**——施工留 10-12 解冻后。设计输入=SKILL.md 现役读者纪律
> （R5-③ 成长含义双段/知识锚只锚已修课程/考研就业双视角/禁行业评论腔）+ 读者环两期数据点。

## 一、schema 全文（v1 草案）

```yaml
# domain/<domain>/reader.yaml —— 读者画像（每领域一份；单人自用=每画像一份）
reader:
  id: chip_reader_v1            # 画像实例名（一人可有多画像：学习画像/求职画像分开）
  version: 1

  # ---- 静态画像：决定「谁在读」----
  profile:
    stage: "大二在读"            # 自由文本
    major: "微电子"
    goals: ["考研", "就业"]      # 视角开关（数组）：驱动「考研视角/就业视角」段生成
    time_budget_minutes: [12, 15]  # 阅读预算：决定条数上限与深度档位（对应 X12/深度规格）

  # ---- 知识锚定：教学层的灵魂（对应 SKILL「知识锚只锚已修课程」纪律）----
  knowledge:
    can_anchor:                  # 白名单：生成「知识锚」时只允许从这里取
      - course: 电路
      - course: 模拟电子技术
      - course: 数字电子技术
      - course: 半导体物理
        concepts: [PN结, MOSFET, 能带, 存储层次]   # 课程下可细化到概念级
    cannot_anchor:               # 禁锚清单：这些领域的概念只可「顺带一句带过」
      - 工艺
      - 器件仿真
    anchor_rule: "每条推演/新闻的知识锚必须命中 can_anchor；cannot_anchor 概念出现时显式标注『超出已修范围』"

  # ---- 成长含义：R5-③ 双段的落点池（「对你的后果」必须落在这里面）----
  growth:
    outcome_targets:             # 落点池：岗位/方向/课程/JD 级的具体对象
      - 考研方向选择
      - 实验室与导师方向
      - 就业岗位类型
      - 招聘JD信号
      - 技能投资（课程/工具/项目）
    action_style: "15分钟内可启动、有具体动作对象"
    forbidden_fallback: ["市场扩大", "格局固化", "窗口打开", "值得关注"]  # 行业评论腔黑名单：单独出现即不合格（对读者无操作含义）

  # ---- 语言纪律：教学翻译格的配置化 ----
  language:
    analogy_style: "日常场景类比优先（先类比后术语；如 HBM=贴身数据快递员、光刻=拿光在硅片上印电路）"
    jargon_ladder: true          # 术语阶梯开关：黑话首次出现须配课内语言
    feynman_section: true        # 费曼课开关
    relative_time_verbatim: true # 相对时间照抄（忠实原文五守则之一）
```

## 二、四个设计判断（施工时不可丢）

1. **can_anchor / cannot_anchor 是教学层的机器可查核心。** 现在"只锚已修课程"是 SKILL 文字纪律
   （validate_understanding.py 只查标签后非空——任意文字 PASS，四维评审已定罪）。schema 化后，
   「知识锚是否命中白名单」变成可校验的硬事实。**这条是未来校验器候选（10-12 后评审），本轮只定结构。**
2. **goals 数组驱动视角段，不写死。** 芯片读者 goals=[考研,就业] 出双视角；换一个读者
   goals=[投资] 就出投资视角——"对你意味着什么"的「你」由画像定义，这才是框架和摘要器的分界。
3. **outcome_targets 是落点池，不是枚举牢笼。** R5-③ 的病根是"行业评论穿读者外衣"——落点池给了
   机器判据（后果是否落到池内对象），同时允许画像作者自己扩充池子（自用工具，池子自己养）。
4. **v1 明确不做的事**：多读者路由（单人单画像够用）；画像自动学习（从 reader_feedback.json 反推
   画像修订——记为远景方向，等读者环攒够数据再说）；情感/难度自适应（过度工程）。

## 三、与现有机制的衔接（解冻后施工映射）

| schema 段 | 现在的宿主 | 施工动作 |
|-----------|-----------|---------|

| time_budget_minutes | X12 条数阈值（8-13） | 解耦：X12 是系统规模约束，预算是个体约束，两者并存（读者预算≤系统上限） |

## 四、诚实边界

- 本 schema 未经第二实例验证——AI 领域画像（AI 学习者版）会在施工期当试金石：若 AI 域配置时
  发现字段不够用/多余，回来改 v1→v2，这是设计稿的正常命运
- 「锚点命中白名单」的机器校验属新校验器，冻结期满走 10-12 评审通道，本稿不实现
- 画像数据全部明文 YAML（单人自用，无隐私分层需求）
