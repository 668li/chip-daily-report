## 1. 调研结论摘要：哪些轮子已存在，我们复用了什么

| 已存在的轮子 | 我们复用的设计 | 落点 |
|------|--------------|------|
| **Miniflux**（开源 RSS 阅读器）的抓取调度 | 生命周期状态机核心字段三元组 `state / error_count / next_check_at` + 指数退避（30min×2^n）+ 失败冻结保留不删除——直接照抄其设计（discover.py 文档头自述「抄 Miniflux 设计」） | `discover.py:23-29`（状态机说明）、`discover.py:93-105`（生命周期参数）、`update_lifecycle()` |
| **Google News RSS 本身** | 它是「万能发现源」：条目 `<source url="出版方域名">` 直接给出出版方域名，无需解重定向链——这是全方案最省力的一步 | `gnews_domains()`（discover.py:400-425） |
| **RSS Autodiscovery 惯例** | feed 自动发现标准两步法：先解析首页 `<link rel="alternate" type="application/rss+xml|atom+xml">`，失败再试常见路径清单（`/feed/` `/rss` `/atom.xml` 等 10 条） | `feed_links_from_html()` + `FEED_PATHS`（discover.py:107-109, 576-593） |
| **OPML 订阅交换格式** | 公开 OPML 清单（awesome-rss-feeds-list / tidings-rss）可直接采样 60 条 xmlUrl 作 feed 提示 | `opml_candidates()`（discover.py:431-452） |
| **newsnow 热榜聚合器**（newsnow.busiyi.world 实例） | 免 key 热榜 API，3 个榜 id（cls-hot / wallstreetcn-hot / gelonghui）的 items[].url 提域名 | `newsnow_domains()`（discover.py:458-481） |
| 本仓 collector.py 既有安全形态 | defusedxml 禁 DTD/实体解析、HTML 实体白名单预处理、`_assert_safe_url`（https-only + 解析 IP 拒私网/回环）、响应体大小上限——发现层直接 import 复用（`_xml_fromstring` / `_strip_html` / `_SAFE_ENTITIES`） | `discover.py:80-83`；新防线只补「无静态白名单」场景（重定向逐跳校验、每域 ≥0.8s 礼貌间隔） |
| 本仓 health_check.py（既有源连通性监控） | 它只管「存量源死没死」，不管「发现新源」——发现层补上缺的半环，两者共享 collector 抓取形态 | 交付说明 |

**黑名单调研结论**（2026-09-25 实测，免得后人重踩）：TrendForce RSS（404）、The Elec（403/502）、AnandTech（已关站，**HTTP 200 + HTML 反爬壳陷阱**——200 ≠ 活 feed）、36kr `/feed`、虎嗅 `/rss/0.xml`、Bing News RSS（仅 12 条）、RSSHub / DailyHotApi / 60s API 公共实例（均被 Cloudflare 拦截）。已固化进 `discover.py:38-41` 与 `references/sources.md`「实测黑名单」表。

## 2. 架构

```
[引擎1 gnews 中英]   [引擎2 OPML 种子]   [引擎3 newsnow 热榜]     ← fail-soft，单引擎失败跳过
        └──────────────┬─────────────────┘
                 候选池（发布方主域归一：剥 www. / 移动镜像 m. wap. touch.）
                        ↓
        known 过滤（registry.SOURCES ∪ collector._ALLOWED_HOSTS ∪ state 已有域）
                        ↓  net-new 增量 = 打破信息茧房的增量
        探测四道门：feed 自动发现 → 合法性（HTML 壳/非 feed/无条目拒绝）
                    → 新鲜度（最新条目 90 天内）→ 相关性（芯片词命中 ≥3 且命中条目 ≥2）
                        ↓
        生命周期状态机（Miniflux 式）：
          candidate --过门--> trial --连续 2 次过--> active
          确定性失败：error_count+1，退避 30min×2^n 封顶 7 天，3 连败 → frozen（保留不删）
          瞬时失败（fetch_failed/probe_error）：单独计数，退避封顶 24h，不冻结不改 state
                        ↓
        原子写回 state/discovered_sources.json（.tmp + os.replace）
                        ↓  collector 侧消费（只读，fail-soft）
        ① _dynamic_hosts(): trial/active 域并入抓取白名单（collector.py）
        ② dynamic_rss_collectors(): trial/active 源实例化为 tier=4 RSSCollector 并入 online 采集
```

**安全形态**（发现层要探测未知域名，不能有静态白名单，防线改为运行时校验）：https-only + DNS 解析逐 IP 拒私网/回环/链路本地/保留/多播 + 重定向逐跳校验（`_DiscoverRedirectHandler`）+ 2MB 响应体上限 + 每域礼貌间隔 ≥0.8s + Google News 相邻 query ≥2s；XML 一律 defusedxml。

**分级纪律**：动态源一律 tier=4（线索级，过 gate G3 打 single_low_tier 降级线）——零人工审核的自动源不得与 registry 里 A 级中文权威（tier=3）同级；**采集层新源不自动进 A 级白名单**，引用时仍按既有白名单判定规则分级。

**CLI 契约**：结尾固定打印 `[discover] SUMMARY net_new=X validated=Y promoted=A state_total=T known_domains=K` 供门禁 grep；任何异常 fail-soft，进程 exit 0（argparse 用法错误除外）。

## 6. 已知风险与后续建议

1. **active 池有「泛科技」混入**：pcguide / memeburn / cleanroomtechnology 的样本标题偏消费电子/洁净室而非芯片垂类（state 内 sample_titles 可证）——相关性阈值（≥3 关键词且 ≥2 条目）偏低。建议：trial 期人工过目一次再放行 active，或对 kw_hits 加垂类加权。
2. **candidate 池 29/44 是 fetch_failed**：与本机代理环境强相关，多为瞬时失败；到期的会自动重试翻案。frozen 池当前为空，首次出现 3 连败冻结后建议每周随 full 模式重探一次。
3. **`raw_payload.publisher_domain` 暂无消费点**（collector.py 注释如实披露）：Google News 条目的出版方域名已落盘 data/raw_events.json，但 cleaner/fusion/gate 管线未消费，日报引用回溯属已知待接入项。
4. **8 个 active 的 discovered_via=hint 错标历史无法追溯修复**：修复（对抗审查 #2）只保未来；如需干净统计，可手动把 hint 改回真实渠道（不推荐——手改 state 有污染风险，接受历史瑕疵更稳）。
5. **A 级白名单升级通道是纯人工**：发现层只解决「能不能抓」；若长期无人录 registry，动态源会永远停在 tier=4。建议每月核查 active 池时顺手定级（与 sources.md「每月核查源可用性」的既有维护节奏合并）。
6. **OPML/newsnow 外部依赖**：OPML 清单托管在 GitHub raw（需代理可达）；newsnow 公共实例曾被 Cloudflare 拦（当前直连可用）——两引擎均 fail-soft，失效只降产出不炸进程。
7. **镜像与文档已同步**：`references/sources.md` 末尾手工维护区新增「自主源发现层（2026-09-25 接入）」节（GEN:ALEVEL 生成区零改动）；SKILL.md Step 2 最小插入一条；CLAUDE.md「当前状态」节末尾加一行；三者已同步至 `.trae/skills/chip-daily-report/` 镜像，`check_rules_consistency.py` R1 段全绿。

## 7. 第 4 轮（2026-09-26 主会话复核与池子清洗）

前三轮交付后，主会话对 9 个 high/medium 修复逐条验证了代码真身，并做了一次端到端复判：

1. **修复验证通过**（逐条核实，非采信声明）：词边界匹配（discover.py `_kw_hits_in`）、重定向逐跳安全校验（`_DiscoverRedirectHandler`）、失败二分类（确定性冻结/瞬时退避 24h）、中文词典补齐（台积电/中芯国际/北方华创/实体清单/大基金/靶材/载板/刻蚀/光刻机等 24 词）、动态源 tier=4（gate G3 打 single_low_tier）、镜像全量同步（含 discover.py 入镜像）、tests/test_health_check.py 污染真实 state 的存量缺陷修复。
2. **新增 `--mode rescore`**：门禁升级后对全池 trial/active 用当前门禁复判（确定性不达标降回 candidate、瞬时失败不动）——这是发现层的长期运维能力，以后每次升级门禁跑一次即可清洗池子。
3. **发现并修复「消防水管 exploit」残余**：词边界挡不住全站大 feed 靠几十条里凑 2 条芯片内容刷过绝对数门槛（businesskorea 20 条里 5 条命中 = 恰好 25% 踩线，样本标题是检察新闻/机场时尚/职校招生）。实测全池密度谱（eenewseurope 0.5 / techpowerup 0.4 / electronicsweekly 0.4 / tspasemiconductor 0.35 / wccftech 0.3 / electronicsforyou 0.3 / businesskorea 0.25）后，把相关性门升级为三条件：**关键词 ≥3 且命中条目 ≥2 且命中密度 ≥30%**（0.30 有实测谱背书，非针对单一站点调参）。
4. **三轮 rescore 清洗结果**：memeburn → pcguide → cleanroomtechnology → gagadget → businesskorea 依次被新门禁降级，终池 6 源全部 ≥0.30 实测芯片内容密度（全部 tier=4 线索级，gate G3 标记，人工定级走 registry 通道）。第 6 节风险 #1（泛科技混入）就此闭环——不是靠人工点名，是靠门禁升级 + rescore 机制。
5. **回归**：tests/test_discover.py 40 用例全绿（新增 D14 rescore 全池复判 + 消防水管密度用例）；rescore 全程真实网络执行，state 留痕（每源 evidence.rescore 记录判定时间与结论）。
