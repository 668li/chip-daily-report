> **定位**：四镜反思（追本/降秩/Karpathy/矛盾论）的施工图纸。承 2c9acfa「设计先行、解冻后施工」先例，本文是设计稿，**零代码零配置**。
> **思想出处**：`~/Documents/notes/20261001T132236--追本-日报为什么浅__think.org`（七层钻井）、`20261001T132236--日报项目的秩__rank.org`（十象两根）、`delivery/市场调研_个性化日报产品形态_20261001.md`（外部证据）。
> **一句话**：日报不是文章，是状态机的一次转移打印——`state(t-1) + 今日delta → state(t) + 判断修订`。本设计把缺的 state 补上。

---

## 1. 为什么是它（证据链压缩版）

- **病根自认**（v6.3 轮已录）：推演锚点只从当期九条摘要取，防幻觉纪律把推演地基饿死。第 5 期判词「太浅」。
- **降秩结论**：十象归两根——领域状态模型缺失（由新闻流+回忆顶替）+ 读者状态模型缺失（由静态人设顶替）。详见降秩笔记。
- **外部对照**：市场 41 产品铺满坐标系左三格，死掉的（5am/Huxe）全在打印 delta、无一维护 state；右下格（AlphaSense/Elicit）深得有理是因为买得起底座；右上格（领域厚×读者厚）全市场空置——领域导师引擎的落点。
- **复利论证**（Karpathy）：新闻流没有复利，状态有。每多一期，状态更准、判断更可验。这是单人业余项目唯一养得起的复利资产。

## 2. domain_state.yaml · schema v0

文件位置：`state/domain_state.yaml`（**数据文件，不是规则、不是校验器**，不进 rule_registry）。

```yaml
schema_version: 1
description: 领域状态账本 v0——五个领域变量的「现在时」。每期日报 = state(t-1)+delta → state(t)。置信度口径沿用 forecast_log 的 certainty 三级（高/中/低确定性），不发明新刻度。
updated_in_report: 芯片行业日报_20261001
variables:
  hbm_price_supply:                # 变量 id（稳定，改名须迁移）
    label: "HBM 价格与供需"
    horizon: quarter               # 状态时间常数：day/quarter/year——决定多久必检
    judgment: "……"                 # 当前判断：一句话，含水位/方向，禁止纯事件复述
    as_of: 2026-10-01              # 判断锚定日
    source: ["<文章级URL>", "..."] # 判断依据，≥1 条，文章级（承 [G-1] 口径）
    confidence: "中确定性"          # 高/中/低确定性（与 forecast_log 同口径）
    falsifier: "……"                # 证伪条件：出现什么信号则此判断作废
    history:                       # 修订史（状态版的 forecast_audit，可审计）
      - report: 芯片行业日报_20260930
        delta: "……"
        note: "……"
```

**五个变量起步**（与现有五环节/追踪表对齐，不新造维度）：

| id | label | horizon | 种子来源 |
|---|---|---|---|
| `hbm_price_supply` | HBM 价格与供需 | quarter | signal_history「HBM 价格与供需」streak + 第3/4/5期追踪表 |
| `cowos_advanced_packaging` | CoWoS 与先进封装产能 | year | 追踪表 + 20260925/26 期条目 |
| `export_control_timeline` | 出口管制时间线 | month | forecast_log 中 BIS/实体清单类条目 |
| `technology_route` | 技术路线（base die/先进制程） | year | forecast_log 推演条目 + 20260930 推演样板 |
| `competitive_landscape` | 竞争格局（产能/份额/自研） | quarter | 各期「持续追踪」+ 兑现回顾 |

**每条五字段铁律**：judgment / as_of / source / confidence / falsifier，缺一不可——这是把「防幻觉纪律」从每句话扩到每个状态：**引用状态 = 引用一条自带溯源和证伪条件的仓库事实**。纪律不废，作业面变大（矛盾论的对立统一解法）。

## 3. 更新协议（每期一次状态转移）

1. 生成会话开场**读入** `state/domain_state.yaml`（= LLM 的 RAM；当前做法是每期冷启动，九条摘要即全部内存）。
2. 注入策略（控 token）：**只注入本期预期变化的变量全文 + 未变化变量的 judgment 单行**。不全量贴。
3. 采写照旧（供给链不动）。
4. 收尾执行**状态转移**：有 delta 的变量——旧 judgment 连同本期 report/delta 写入 `history`，新 judgment 落盘，`as_of`/`source`/`confidence`/`falsifier` 同步更新；无 delta 的变量原样保留（显式「→ 维持」，与持续追踪 Δ 列同口径）。
5. **锚点范围修订**（写作纪律层，窄修订已解冻范围）：推演/教学锚点从「当期九条摘要」扩为「当期条目 + domain_state 各变量 judgment」。推演块出现状态判断时，须注一行「锚：domain_state.<变量>（as_of …）」——状态引用与新闻引用在正文里可区分。

## 4. 可验证性接线（挽具挂点）

- **兑现闭环**：状态 judgment 中凡含可验证时点/阈值者，同时写入 `forecast_log.json`（现有通道，零新机制）→ 兑现回顾四态计分板照读 forecast_audit.py 输出。**状态与推演账从此互相咬合：状态是判断的现在时，推演账是判断的 futures。**
- **审计接线（10-12 后施工）**：校验器新增检查——每条 variable 必有五字段；judgment 变更必有 history 行；falsifier 非空。在此之前靠 SKILL 纪律约束（自检表加一项）。
- **X7/gen_rules 关系**：domain_state 是数据不是规则，不进 rule_registry；若未来出现状态相关阈值（如变量数下限），走 registry 通道，禁止改脚本字面量（既定铁律）。

## 5. 种子数据 v0 怎么来

- **只整理，不爬取**：来源限五期 forecast_log / forecast_calibration / signal_history / 各期持续追踪表与兑现回顾。
- 每变量一条 v0 判断：`seed: true`、`as_of` = 整理日、source 引用对应期日报原文 URL。
- **诚实降档**：v0 判断是「整理出来的」不是「新调研的」，confidence 一律在原判基础上降一档；source 不足两条的标单源 ⚠（承 [G-3] 口径）。

## 6. 读者轴对称挂接（第二根轴）

- 领域轴 = 本设计；读者轴 = `delivery/读者画像schema_v1设计稿_20261001.md`（已落盘）。`日报 = f(领域状态, 读者状态)`。
- 挂接点：教学层「今日一课」的锚从 `reader.knowledge.can_anchor` 取（只锚已修课程——画像已定）；状态修订的「对你意味着什么」从 `reader.growth` 落点池取落点（考研/就业/技能）。
- 两轴共用同一条设计公理：**状态 + 溯源 + 证伪**。读者侧的 delta 已有采集器——reader_feedback 四问就是读者状态的 state transition 输入，第 6 期起四问应加「指哪一节」（v8.1 遗留改进）。

## 8. 试产节（第 6 期，预注册防事后改判定标准）

- **范围**：只试 `hbm_price_supply` 一个变量。
- **流程**：第 6 期生成前从五期账本整理该变量 v0 → 写作时按第 3 节协议引用 → 期末写回 delta → 兑现审计照走。
- **观察点**（现在写下，期满照此打分）：① 推演块是否首次出现「状态判断」（对照第 5 期推演逐条判）；② 读者四问对推演/今日一课的反馈走向；③ 兑现审计能否把 v0 判断接进四态计分板。
- **诚实边界**：单变量单期，不构成对整座模型的检验；试产失败（无状态判断出现或读者无感）则回设计稿改，不硬推全量。

## 9. 不做什么

- 不做自动状态更新（先人肉一期，跑通再谈自动化——极简构建主义）。
- 不爬新数据源（v0 只整理存量）。
- 不动 B 档抽取节奏（那是零行为变更重构，与本设计并行不悖）。
- 不加任何门禁/校验器（冻结纪律）。
- 不碰已否决的产品形态方向（问身份→自动接源→让他登，同质化红海，不再提议）。
