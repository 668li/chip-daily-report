## 3｜工作方式：grill-with-docs 的自主化改造

原版 grill-with-docs = 「设计树 + 轮次追问 + ADR/术语表副产品」。长任务里没人可追问，改造为：

- **设计树先行**（Phase 0 产出 delivery/设计树_护城河冲刺_<D>.md）：本轮所有决策画成一棵树（心跳怎么恢复、链路怎么接、门禁怎么扩、评审标准是什么……），每个节点标三色：〔已约定〕引 CLAUDE.md/CONTEXT.md/评审报告原文；〔证据〕引调研结论；〔自决〕写 ADR。只展开前提已定的下游决策。
- **ADR 制**（delivery/ADR_<D>.md）：每条〔自决〕记录 背景/选项/决定/复审条件。用户事后推翻某条 = 只改那一条 ADR，不返工全树。
- **术语表副产品**：本轮新造的任何概念（指标名、机制名）当场落进 CONTEXT.md 或 references/ 术语表，禁止只用自己发明的黑话不留档。
- 事实自己派子代理查，绝不假装询问用户；没有用户在场时，决策不悬空——要么有约定，要么有证据，要么有 ADR。

## 4｜护城河论（待攻击的假设 = 调研的靶子）

当前差异化论点五条，调研的任务是**证伪**它们，不是赞美它们：

1. **每日心跳 + 读者唯一教学层**：为一个人教学（黑话三档翻译/今日一课/费曼/知识锚只锚已修课程/成长含义），不是向一群人播报。
2. **推演可问责**：验证窗口 + 互斥剧本 + 四态兑现回顾 + 判据不可篡改——绝大多数日报/摘要 agent 从不回查自己说过的话。
3. **诚实性工程**：文章级溯源（域名根=伪追溯 FAIL）/ ≤72h 时效账本 / 高信号单源 WARN / 撤稿机制。
4. **批评代谢引擎**：评审发现必须转化为「缺陷样本回归红灯」的门禁检查项，系统越挨骂越硬。
5. **自主发现层**：三引擎发现 + Miniflux 式生命周期 + 密度门禁——源池自愈，不是静态 OPML。

前置声明：**这五条全部以「每日心跳恢复」为前提**——不复利的差异化不叫护城河。猜想：2+3+4 的组合在开源世界无同类，请用证据确认或打脸。

## 5｜阶段计划（并行流水线，总计 4h+；各阶段边界跑 date 对表）

### Phase 0 · 对齐与设计树（20min）
读 §1 指定文档 → 列决策树 → 落 ADR（含 §0 四问处理）→ TodoWrite 建全量任务 → commit。

### Phase 1 · 发射调研（15min，只发射不等待）
把 4 份调研任务书写准（验收标准见下），派 4 个 github-researcher（环境无此类型则用通用研究代理）**并行发出、转后台跑**，随即进入 Phase 2。主上下文严禁串行刷网页。

- **A 组 · AI 新闻日报/摘要 agent**：GitHub stars≥300 的中英文项目。选题/去重/摘要/发布怎么做。
- **B 组 · 预测可问责系统**：prediction tracking / forecast scoreboard / eval journalism / 「回查自己旧论断」类项目。
- **C 组 · 教学型内容 agent**：tutor / Feynman / 为单一学习者做日报或知识追踪的项目。
- **D 组 · 溯源与可信度工程**：citation verification / provenance / 谣言门禁类新闻项目。

每组验收：结论带 repo 链接+证据；**主会话每组抽查 2 条链接可达性（走代理）后才采信**——子代理可能编造 repo，查无实据就写「查无」。免重复调研对照组（直接引用已有结论，不派活）：Miniflux/FreshRSS（生命周期）、RSSHub（AGPL+公共实例 403）、feedsearch-crawler（设计复用）、newsnow、DailyHotApi。

某组超时/失败：不等，用已有结论出地图，缺组如实标注。

### Phase 2 · 主迭代循环（≥120min，循环制）
每个循环 = 选任务 → 实现 → 门禁三件套（26 项 + pytest + X7）→ 记台账 → commit。**循环内不跑对抗评审**（正式评审只在 Phase 3，半成品有门禁就够了；批评代谢的价值在转化不在频次）。单任务 45min 出第一版；30min 无绿即回滚记账换下一个。任务池按序领：

- **P0-0 恢复每日心跳**（按 Q1 结论）：daily_runner.py 一条命令串起 discover quick → 生成 → 校验 exit 0 → HTML 构建；失败 = 非零退出 + 明确报错哪步炸了；按 Q1 注册定时任务并在交付说明给删除方法。**验证标准：runner 完整 dry-run 一次成功。**这是护城河的前置条件。
- **P0-A gate→候选链路**：把 gate/prepare_candidates 接进每日生成，动态源 tier=4 走 G3 降级线落地。
- **P0-B validate_understanding.py v1**：把占位转实，但 v1 只做**存在性校验**（teach 槽非空/今日一课节存在/费曼节存在/每个推演块含知识锚+成长含义+验证窗口）——「知识锚↔已修课程语义一致性」需要先结构化课程清单，明确划给 v2 不做。挂进门禁族（遵守铁律 11）。**验收含防注水锚：从第 1 期构造缺陷样本（如推演块缺知识锚的旧式文本），新校验必须对它 FAIL（用临时副本测，不碰真实历史文件）。**
- **P1-C 采集准入前移**：候选卡无文章级 URL 不入池——把 G-1 从验后拦截前移到采中准入，消灭事后溯源回填。
- **P1-D publisher_domain 消费点**：数据已落盘，接进 value_score 或 gate 分级。
- **P2-E weekly_review KeyError**（按 Q3，30min 盒）。
- **P2-F 调研快赢项**：Phase 2.5 出的「抄什么清单」top1-2 动态插入。

### Phase 2.5 · 对标消化（20min，后台调研回来即做；45min 仍未回则主动查收）
产出 delivery/对标报告_护城河_<D>.md：对比矩阵（≥8 项目 × 八维度：选题自动化/溯源强度/时效诚实/预测回查/教学层/质量门禁/源发现生命周期/批评代谢）+ **抄什么清单**（对唯一读者的价值排序，这是主产出）+ 避什么清单 + 护城河地图（五条论点逐条判：独占/领先/持平/落后）。「落后 × 对唯一读者重要」才进任务池——多用户扩展、花哨 UI 之类落后无关紧要。

### Phase 3 · 试产第 2 期（60min）
按 SKILL.md 全流程生成 <D> 当日日报（P1-C 若已落地则候选天然带文章级 URL）→ 26 门禁 exit 0 → **本轮唯一一次正式对抗评审**（project-critic），评审 brief 第一判据必须是读者价值：勇谚今天能带走什么、能复述什么、对他的考研/就业产生什么动作。判定处理：**P0 必须归零，合法路径 = 修复内容 或 转化为门禁/流程并落地，禁止仅辩护**（诚实标注如「N=0 已标周报」是合格处理）；P1 逐条决定「转门禁/记台账/说明为何不修」。全部指标进台账。

### Phase 4 · 收尾（30min）
台账终版 → 复盘 doc（5Why + 继续做/停止做 + 运气vs能力）→ CLAUDE.md 现状化 → 镜像逐字节同步 → commit + push → 未竟项写 delivery/会话交接_<D>.md。

## 6｜迭代台账（改进必须可度量，且不可注水）

delivery/迭代台账.md，首行记基线——**注意事实精确：评审 P0×3/P1×4/P2×5 是针对优化前 14 条版的判定，评审优化版（18 条）门禁复验 exit 0 但未经二次评审**；第 2 期是该系统第二次评审。每个循环必须挪动至少一个指标并如实记录（负 delta 也记，写原因）：

门禁项数 · 评审 P0/P1/P2 数 · ≤72h 条目比例 · 文章级比例 · A 级源占比 · pytest 绿数 · 动态源 active 数 · 推演按期兑现数 · **心跳连续天数（新增）**。

两条防注水/防过度解读规则：
- 门禁项数增长必须伴随缺陷样本回归红灯（见 P0-B），否则不计入进步。
- 台账诚实注记：每期评审样本量=1，delta 是方向性信号不是统计结论；单门禁项数、单期 P0 数不得单独作为「系统性质变」的证据。

## 7｜防漂移纪律

- TodoWrite 全程驱动：阶段开始/结束必更新，一眼可见进度。
- **不问问题、不等回答**：自决 + ADR（唯一例外：删数据/强推等破坏性操作才停）。
- 调研一律后台子代理并行；主上下文只消费结论，不搬运网页原文。
- 被任何事阻塞 >15min：记账（阻塞原因 + 已试路径）→ 换任务，禁止空转。
- 上下文变长信任摘要机制继续干，不要提前收工；续命靠 delivery/ 里的文档，不靠对话记忆。
- 禁改 data/ 回归基线；禁改已入库推演判据；禁手工同步注册表三件套。
- 阶段边界跑 date 对表，超时盒 25% 以上必须砍范围，不许静默挪预算。
