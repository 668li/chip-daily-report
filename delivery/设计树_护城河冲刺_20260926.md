# 设计树 · 护城河迭代冲刺（启动日 2026-09-26）

> 规则：每个节点标三色——〔已约定〕引既有文档原文；〔证据〕引调研/实测结论；〔自决〕记 ADR（delivery/ADR_20260926.md）。
> 使命：恢复每日心跳，把「批评→门禁」做成可证伪机制，用试产第 2 期证明一个冲刺内 measurable 变强。

## 根节点：第一矛盾
- 〔已约定〕CLAUDE.md「自动化现状」：F4 已死、当前环境无定时任务，日报停摆中。护城河五条论点全部以每日心跳为前提，不复利的差异化不叫护城河 → 本轮优先级：心跳 > 链路与门禁 > 对标。

## 分支 1 · 心跳怎么恢复（P0-0）
- 〔已约定〕发射前 Q1 无人应答 → 按推荐执行：`scripts/daily_runner.py` 一条命令 + 本 harness CronCreate 注册每日唤起；失败即响 = 定时会话运行结果用户直接可见 + runner 非零退出；注册可一键删除（方法写进交付说明）。→ ADR-001
- 〔自决〕runner 与 LLM 分工：runner 只做**机械链路**（discover quick → prepare_candidates → validate → build HTML），**内容生成留在 LLM 会话**（SKILL.md 六步流程）——日报正文创作无法纯脚本化，这是与旧 F4（WorkBuddy 全自动含 LLM 步骤）的本质差异。定时任务的本质 = 每天唤起一个 LLM 会话按 SKILL.md 干活，runner 是它的一命令入口与验收器。→ ADR-002
- 〔自决〕心跳节奏沿用历史 F4 约定：周一至五 08:00（周末新闻薄、且历史 convention 如此）；台账「心跳连续天数」按工作日记。→ ADR-001 复审条件里注明可改每日 7 天
- 验证标准：runner 完整 dry-run 一次成功（不真发报，只验链路）。

## 分支 2 · 链路怎么接（P0-A / P1-C / P1-D）
- P0-A gate→候选链路：
  - 〔已约定〕CLAUDE.md 已知债「gate 候选链路待接入」；v7 已上线发现+采集层，动态源 tier=4 走 gate G3 降级线。
  - 〔自决〕接法：runner prepare 阶段跑 `prepare_candidates.py`（online→clean→fusion→gate 一键，不落盘 data/ 基线）→ 产物写 state/，每日生成会话（LLM）开工前先读 gate_report + 候选池作为 Step2 搜索的底池。接口以实际脚本现状为准，最小改动。
- P1-C 采集准入前移：
  - 〔已约定〕评审 P0-1：11/14 来源是站点首页伪追溯；v7.1 [G-1] 只能验后拦截，回填成本已实付 9 处。
  - 〔自决〕落点在**采中**：cleaner/gate 阶段对候选条目的 URL 做文章级判定（域名根/仅斜杠/无路径 = 不入池），让每日候选天然带文章级 URL。具体文件看完 cleaner.py/gate.py 现状再定，判定逻辑与 validate_report.py [G-1] 同口径。→ ADR-006
- P1-D publisher_domain 消费点：
  - 〔已约定〕CLAUDE.md 已知债「publisher_domain 落盘但管线暂无消费点」。
  - 〔自决〕最小接法：接进 gate 分级或 value_score 加分（官方一手域名如 tsmc.com/amkor.com/asml.com 提置信/加分），看 value_score.py 现状选改动面最小者。
- P0-B validate_understanding.py v1：
  - 〔已约定〕CLAUDE.md 已知债「仍为规划占位」；发射提示词划界：v1 只做存在性校验（teach 槽非空 / 今日一课节存在 / 费曼节存在 / 每个推演块含知识锚+成长含义+验证窗口）；「知识锚↔已修课程语义一致性」明确划 v2 不做。
  - 〔自决〕挂接方式：**独立脚本 + daily_runner 串联调用**，不塞进 validate_report.py（26 项提数不变，全部提数处口径改为「26 项硬校验 + 理解层存在性校验」）。→ ADR-004
  - 〔已约定〕验收含防注水锚：从第 1 期构造缺陷样本（推演块缺知识锚的旧式文本，临时副本）→ 新校验必须 FAIL；不碰真实历史文件。
  - 门禁不追溯历史期：只对当期新日报要求 exit 0。〔已约定·铁律〕

## 分支 3 · 门禁怎么扩（批评代谢引擎）
- 〔已约定〕v7.1 先例：评审发现 → [G-1]~[G-4] 规则级落地 + 合成样例验证。
- 〔已约定〕发射提示词防注水规则：门禁项数增长必须伴随「第 1 期缺陷样本回归红灯」否则不计入进步；台账每期评审样本量=1，delta 是方向性信号不是统计结论。
- 本轮新增门禁 = P0-B 理解层校验（带缺陷样本红灯）+ P1-C 采集准入（带对抗样本：首页 URL 候选必须被拒）。

## 分支 4 · 评审标准是什么（Phase 3 试产第 2 期）
- 〔已约定〕Q2 无人应答 → 跑第 2 期全循环（生成→门禁→对抗评审），它是一切迭代的验收载体。
- 〔已约定〕评审 brief 第一判据 = 读者价值：勇谚今天能带走什么、能复述什么、对考研/就业产生什么动作。
- 〔已约定〕P0 归零 = 修复内容或转化为门禁/流程并落地，禁止仅辩护；P1 逐条决定转门禁/记台账/说明为何不修。
- 〔证据〕第 1 期评审（delivery/日报质量评审_20260926.md）：优化前「有条件值得读」，P0×3（伪追溯/单源加戏/时效失效）已由 v7.1 门禁+回填断根；第 2 期要验证的是「新门禁下能否天然产出合规报告」而非再次人工回填。

## 分支 5 · 对标怎么用（Phase 1→2.5→P2-F）
- 〔已约定〕四组调研（A 日报 agent / B 预测问责 / C 教学层 / D 溯源工程）+ 已知对照组（Miniflux/FreshRSS/RSSHub/newsnow/DailyHotApi/feedsearch-crawler 直接引用不重调）。
- 〔已约定〕验收：主会话每组抽查 2 条链接可达性（走代理）后才采信；查无实据写「查无」。
- 〔已约定〕对标报告 ≥8 项目 × 8 维度（选题自动化/溯源强度/时效诚实/预测回查/教学层/质量门禁/源发现生命周期/批评代谢）+ 抄什么清单（对唯一读者价值排序）+ 避什么清单 + 护城河地图（五条论点逐条判：独占/领先/持平/落后）；「落后 × 对唯一读者重要」才进任务池。
- 猜想待证伪：「2 推演可问责 + 3 诚实性工程 + 4 批评代谢的组合在开源世界无同类」。
- P2-F：对标「抄什么清单」top1-2 动态插入任务池。
